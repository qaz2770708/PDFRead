# 数据文件、保存与恢复（M5）

## 配对与迁移

`报告.pdf` 默认保存到 EXE 同级的 `data/<PDF的SHA-256>/报告.pdfdata`。同名而内容不同的 PDF 由哈希目录隔开；相同内容改名或复制后复用已有文件，不重复生成记录。index.json 只是路径索引，数据文件内的 sourceHash 才是版本依据；没有旧索引时仍能按哈希目录加载。

旧版 `data/<hash>.pdfdata`、PDF 旁边的同名数据，以及直接复制到 data 根目录的同名数据均可导入，导入源文件保留，之后写入新默认位置。同名候选有多份时不任意挑选，可用右栏“数据 → 加载数据文件”明确选择。当前默认位置已有数据时优先使用已有记录；手动加载另一份有效数据前会确认替换，并保留备份。

迁移有两种方式：

1. 复制 PDF 及整个 data 文件夹到新电脑的软件目录。
2. 用“数据 → 导出随 PDF 的同名数据”生成 `报告.pdfdata`，与 `报告.pdf` 放在同一目录后一起复制，新电脑打开 PDF 会导入它。也可通过“加载数据文件”手动选择。

“另存并切换”（Ctrl+Shift+S）将当前状态写到用户选择的位置，成功后后续保存使用新位置；“导出”只生成便携副本，后续编辑仍保存到当前文件。手动另存到默认目录以外的文件时，迁移应把这份文件一起复制。

## SHA-256 不匹配

- **新建记录**：当前版本从空白开始，旧版本与旧哈希文件保留。
- **沿用旧注释**：再次确认后复制最近版本的注释、便签、书签与进度；原记录保留。当前 PDF 页数以外的标注只保留在旧记录中，当前记录不加载它们。
- **不加载数据**：本次仅阅读，不加载旧记录，也不自动写数据或进度。若新增标注，需要显式另存后才持久保存。
- **取消**：停止打开；已有标签保持打开。

哈希依据 PDF 全部字节，元数据或增量修改也会触发不匹配。新路径、内容也变化且没有同名数据或旧路径索引时，无法推断来自哪份旧 PDF，按新文档打开；需要时手动加载旧数据。

## 保存与失败

正文/样式停止修改 400ms 后保存，阅读位置延迟 800ms；注释几何提交、书签修改、Ctrl+S、结束编辑、切换标签、关闭与拖出窗口会提交相应修改。输入中的编辑立即显示“未保存”，提交时显示“保存中…”，完成显示“已保存”。

写入先生成 `.tmp`，刷新到磁盘并验证结构和完整性，再原子替换正式文件，上一份有效正式数据成为 `.bak`。保存失败不提前推进内存修订号，不删除有效备份，修改留在内存；提示重试、另存或稍后处理。一次失败后暂停反复弹窗，Ctrl+S 或数据菜单可重试。未成功保存时关闭会被阻止。

保存前后检查打开时的数据指纹，并用 `.lock` 排除本程序的并发写入；发现其他进程修改、替换或删除数据后，拒绝覆盖，需重新加载或另存。索引写入失败不影响已经完成的数据保存，状态提示的悬停说明会显示索引问题。

## 恢复、备份与升级

打开时验证正式、临时和备份文件。较新的完整 `.tmp`、正式文件损坏时可用的 `.tmp`/`.bak` 均需用户选择恢复。临时文件不完整则不能作为恢复候选。拒绝较新临时数据时，会先保护其副本再移出活动临时位置，避免下次重复询问。

恢复前保留候选副本；正式文件损坏时也保留损坏原件。保护副本和升级原件位于 `data/_backups/<原始内容指纹>/`，不会因下一次保存被覆盖。备份失败时停止恢复或升级，原件不改写。所有数据均损坏时明确提示并取消加载；不会自动创建空数据覆盖它们。遇到比当前更新的格式会停止加载，避免回退到旧备份后覆盖新格式。

v1～v5 在反序列化升级前先保留原始字节副本，验证后才在内存升级；保存时再原子写成 v6。升级失败保留原文件和备份。v6 增加内容完整性校验及便签副文本；旧文本字体默认保留 Microsoft YaHei UI，新文本批注为宋体。请勿用旧软件写入新版数据。

恢复只能找回已完整写入的快照，异常发生前尚在 400ms/800ms 延迟窗口中的最新输入可能来不及保存。原 PDF 始终只读，不承担恢复数据的存放。
