# HeroUI 界面与验收

## 界面实现

使用 npm 注册表核实并锁定的 HeroUI 3.2.7（@heroui/react、@heroui/styles），配合 React 19 与 Tailwind CSS v4。WinForms 作为 Windows 桌面宿主，WebView2 显示真正的 React/HeroUI 界面，不是给旧控件换色。页面仍由 Windows PDF API 输出，批注编辑、书签、数据恢复和 PDF 导出继续使用既有 C# 内核。

窗口标题栏、文件标签、右侧工具、目录/书签/缩略图、快捷样式、右键菜单及专业属性重做为纯色界面。工具背景轻透明，图标保持可辨；有独立工具留白，宽页和旋转页不会被按钮盖住。各页面按自身宽度在阅读区布局，超宽页可横向滚动。外部浏览器导航、下载和默认浏览器菜单被阻止；应用资源随包离线分发。

## 构建

需要 Node.js 22.12+、.NET SDK、.NET Framework 4.8 targeting pack。build.ps1 先调用 build-ui.ps1，再构建桌面宿主并复制 DLL 和 web 资源。首次按 lockfile 执行 npm ci，已有依赖可用 -NoRestore；build-ui.ps1 -NoInstall 单独做 TypeScript 检查和前端构建。

package.ps1 生成 outputs/PDFReader-HeroUI.zip。运行需要 Microsoft Edge WebView2 Runtime；保留全部 DLL、web 目录和已有 data。v6 数据格式及文件配对不改变。

## 验证

- TypeScript 严格检查、Vite 生产构建、.NET Release 编译。
- 原十一组内核集成验收通过：阅读、缩放、目录/书签、存储及恢复、多窗口、各类批注、便签、导出等。
- ModernUiAcceptance 在正常桌面用户进程中启动真实 WebView2，通过内嵌浏览器 SDK 驱动实际控件和指针事件，未使用假 PDF 或前端模拟数据。
- 检查 HeroUI 版本、实际 PDF 图像、可见控件无渐变；截图检查阅读页、书签、快捷样式、专业属性、右键菜单和缩略图布局。
- 细滚轮累积缩放；中文批注输入、字号加减、预设颜色、缩放后保留编辑框；便签正文与副文本保存。
- 指针新增矩形、移动、四角调整、撤销/重做；专业属性弹窗打开和关闭。
- 浏览器连续滚动保存页内位置；书签记录真实浏览器视口，支持层级调整和右键菜单；缩略图及目录跳到正确页索引。
- 新界面触发 PDF 导出，原文件哈希不变；关闭重开恢复进度、书签和注释。
- 自定义窗口最大化/还原、多标签独立进度、独立窗口迁移；迟到的滚动消息包含文档身份，不能改写其他标签进度。
- 将最终 ZIP 解压到独立目录，加载其中的 EXE 和离线 web 资源：确认真实 HeroUI 3.2.7、PDF 页面渲染、批注桥接与独立数据保存、PDF 导出及原文件哈希不变。压缩包不包含本地数据、浏览器用户配置或 node_modules。

运行 ./test.ps1 -NoRestore 为内核验收；正常桌面 PowerShell 添加 -ModernUI 运行界面验收。Codex 的受限命令子进程环境会阻止 WebView2 渲染器/显卡子进程启动，本次通过 computer-use 启动桌面验收进程，并使用 WebView2 CapturePreviewAsync 检查真实渲染；没有关闭浏览器沙箱或系统安全功能。桌面窗口截图接口超时，因此未把物理鼠标人工操作当作已完成的人工验收。

## 运行边界

浏览器只是呈现与输入层；所有改动经文档身份校验后进入独立数据内核。拖动预览不写入未提交几何，文本仍延迟自动保存。异常的 WebView2 启动/进程失败会明确提示并恢复基础界面，避免留下无法使用的白屏。

F2 专业属性使用 HeroUI；打开/保存/覆盖等文件选择以及数据恢复/错误确认保留系统或基础提示流程。界面缓存不存放 .pdfdata，退出清理会释放宿主与文档资源。

## 绘制响应、视觉居中与图标更新

批注拖动使用浏览器 requestAnimationFrame 本地预览，不再依赖 180ms 内核状态轮询。移动消息每帧合并，手写保留合并事件中的中间采样；抬笔立即冲刷最后一帧，等待内核提交确认再撤下预览，取消时清理待发消息。拖动期间暂停完整状态回传，文本框/便签几何也在本地反馈，后台仍负责坐标、撤销和持久化。页面组件缓存避免每次指针更新重绘所有页面；内核手写包围盒改为增量更新。

高亮和下划线拖动时先显示区域反馈，抬笔后由原文字解析器精确贴合文本区域。实时反馈并不意味着提前保存；实际延迟仍受设备负载、PDF 复杂度和显示刷新率影响。

画布左右预留等宽工具空间，页面中心与整个画布中心一致；最大化、还原及打开导航面板时使用相同规则。极窄窗口或超宽页面仍可横向滚动。

EXE 嵌入原创多尺寸 PDFRead.ico（16/24/32/48/64/128/256），窗体显式使用 EXE 图标。resources/build-icon.ps1 可重新生成图标；本次不更改 Windows 默认程序关联。

新增真实 WebView2 验收：最大化页面中心偏差小于 6px；阻断后台 move 消息时本地预览仍可见；抬笔后几何正常提交；一次高频手写保留至少 60 个中间点。原有缩放、编辑、保存、目录、多窗口及导出流程继续验证。

缩略图固定单列，占满侧栏内容宽度并保留页间空隙；按预览宽度与显示缩放比例请求清晰图像，继续按可见范围懒加载。新增布局验收覆盖普通、窄窗口和最大化窗口，确认预览从上至下单列排列及页码跳转。

## PDF 原文选择与复制

新增独立 PdfTextLayer.tsx：使用现有 PdfPig 文本解析服务提供的文字、归一化页面位置和旋转方向，在 PDF 图像上覆盖透明 DOM 文字。文字层只负责临时选区；页面图像仍由 Windows PDF API 渲染，注释层、撤销记录和 .pdfdata 格式保持原有职责。

默认“选择 / 移动”工具下可从文字处拖选、双击选词、三击选择按行距与缩进推断的段落；已有批注优先接收编辑操作。右键提供复制、选择此段、选择本页、取消文字选择；Ctrl+C 复制选区，Ctrl+A 选择当前页文字。输入框内部保留原生编辑快捷键。切换到批注绘制工具时清除文字选区，文字层不拦截指针。

页面接近视口时才加载文字，解析服务缓存最近 16 页，随文档释放。复制通过桌面宿主的 Unicode 剪贴板接口完成；剪贴板占用或解析失败会明确提示。右键复制使用打开菜单时捕获的文字，避免菜单焦点转移丢失选区。选区不会写入 PDF 或数据文件。

没有可提取原文时异步自动启动本机 Windows OCR，将识别词框按渲染图像位置归一化，不再只提示需要 OCR。OCR 依赖系统安装的识别语言，图像清晰度、特殊字体、倾斜文字、复杂多栏和 PDF 内部文字顺序可能影响识别准确性、选区贴合与复制顺序；段落边界是几何推断，不作为 PDF 的语义段落承诺。复制保留文本行边界，不复制页面格式。

验收覆盖真实 WebView2 双击选词、三击当前段落、Ctrl+C、Ctrl+A 和右键复制；后续继续执行现有批注、缩放、书签、目录、保存重开、窗口迁移及导出流程，确认文字层不会截获绘制操作。测试复制时在内存中保留并恢复原有剪贴板。

### 自动 OCR 回退修正

有文字且坐标有效的页面优先复用原文；无文字、无有效位置或解析失败的页面，使用 Windows.Media.Ocr 在本机对 Windows PDF API 输出的页面图像识别，词框映射到相同页面坐标。不会联网传输页面，不修改原 PDF 或注释数据。文字请求在后台串行去重，同一文档最近 16 页缓存；关闭文档后丢弃异步结果。双击显式按浏览器 Intl.Segmenter 词边界建立选区，避免仅依赖透明绝对定位文字的默认双击行为。

选择工具下文字准备期间显示短暂加载状态；识别失败只显示可点击重试的简短按钮，详细原因在悬停提示中。缺少识别语言、空白页和低清晰度页面不能保证有识别结果，不再将这些情况一律断定为扫描页。

TextSelectionAcceptance 生成只有图片的 PDF，确认 OCR 返回可复制词及归一化坐标；可额外传 PDF 路径测试正文。RealPdfSelectionAcceptance 可在正常桌面传入实际 PDF 路径，检查封面及第 21 页双击选择和中文剪贴板复制；测试数据和截图仅在 work 下。此次使用用户提供的实际文件通过了封面 OCR 及正文原文选择验证；用户文档和截图不打包、不入库。
